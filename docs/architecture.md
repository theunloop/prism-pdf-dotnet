# Architecture

## Two layers, always

The core's binding author's guide is prescriptive here, and this SDK follows it exactly:

> Every binding has exactly two layers:
>
> 1. **The raw layer** (`NativeMethods`, `_prismpdf`, `sys`, …): one flat, mechanical, 1:1
>    projection of `prismpdf.h`. No logic, no renaming beyond the language's FFI syntax.
> 2. **The idiomatic layer**: the canonical object model. This is the public API and the only thing
>    user code sees. It is where the ownership and error conventions are enforced, once, so user
>    code cannot leak, double-free, or misread a status.

```
     your code
         │
         ▼
┌────────────────────────────────────────────────────────┐
│  idiomatic layer   namespace PrismPdf                   │
│  Document, OpenOptions, Permissions, SignSettings,     │
│  the Collections/ lists and their borrowed items       │
│                                                        │
│  · every status is checked exactly once, here          │
│  · every owned string/buffer is copied and freed here  │
│  · every handle's lifetime is a Dispose(), here        │
└────────────────────────────────────────────────────────┘
         │  internal
         ▼
┌────────────────────────────────────────────────────────┐
│  raw layer         namespace PrismPdf.Interop           │
│  NativeMethods — 386 [DllImport] declarations          │
│  NativeLibraryResolver — where libpdf_ffi lives        │
│                                                        │
│  · no logic, no ownership, no error handling           │
│  · internal: user code cannot reach past the wrapper   │
└────────────────────────────────────────────────────────┘
         │  P/Invoke, cdecl
         ▼
    libpdf_ffi.dylib / .so / pdf_ffi.dll
         │
         ▼
    the Rust engine (pdf-ffi → pdf → the workspace)
```

## The raw layer is generated, not written

`src/PrismPdf/Interop/NativeMethods.cs` carries an `<auto-generated>` header and means it. It is
produced by `build/gen_native_methods.py`, which parses `native/include/prismpdf.h` and emits one
declaration per export.

That is not laziness — it is the cheapest way to make "a 1:1 projection of the header" literally
true rather than aspirationally true. Vendor a newer header, regenerate, and the diff you review is
exactly the ABI's additions, restricted to the areas this SDK binds.

```bash
python3 build/gen_native_methods.py          # rewrite
python3 build/gen_native_methods.py --check  # fail if stale (wire this into CI)
```

The generator holds one hand-maintained list: `AREAS`, the exports this SDK binds. Adding a new
area means adding its export names there and regenerating — then writing the idiomatic layer for
them.

### The three projections C# cannot express directly

| C | C# | Why |
|---|---|---|
| `bool` (`stdbool.h`, one byte) | `byte` | Blittable in and out, no marshalling attribute, no ambiguity about width. `Native.ToBool` / `FromBool` convert at the boundary. |
| every opaque `PrismPdf… *` | `nint` | The raw layer must not know which handle is which; the wrapper types do. |
| `char *`, `uint8_t *` | `byte*` | Strings are never auto-marshalled. An owned `char **` out-param must be copied and then released with `prismpdf_string_free`, which no built-in marshaller knows how to do. |

Calling convention is pinned to cdecl on every declaration. The default (`Winapi`) happens to be
cdecl everywhere .NET runs today except Windows x86; pinning it costs one attribute and removes the
exception. Each declaration also sets `ExactSpelling`, so the runtime never probes for the `A`/`W`
suffixed variants a Rust `extern "C"` library does not have.
`NativeSurfaceTests.EveryDeclaredExport_UsesCdecl` enforces both.

## The target framework

The SDK targets **`netstandard2.0`**, which is the widest reach a .NET library has: .NET Framework
4.6.1+, .NET Core 2.0+, every .NET 5+ release, Mono, Unity and Xamarin all consume it. Building and
testing this repository still needs a .NET 8 SDK — that is the compiler, not the target.

That choice is the reason for three things that would otherwise look like odd style:

| What | Why |
|---|---|
| `[DllImport]`, not `[LibraryImport]` | The `LibraryImport` source generator is .NET 7+. The projection is otherwise identical; cdecl moves from `[UnmanagedCallConv]` onto the attribute. |
| `src/PrismPdf/Compat/` | netstandard2.0 has no `NativeMemory`, no `ArgumentNullException.ThrowIfNull`, no `IsExternalInit` for `init`/`record`, no `ModuleInitializerAttribute`, no `CallerArgumentExpressionAttribute`. Each is re-declared there, `internal`, throwing exactly what the BCL versions throw. |
| `NativeLibraryResolver` uses reflection | `NativeLibrary.SetDllImportResolver` is .NET Core 3.0+. The resolver installs itself through it when the *hosting* runtime has it, and pre-loads the library through the platform loader when it does not — see [native-build.md](native-build.md). |

Two capabilities are given up by targeting netstandard2.0 rather than `net8.0`: the `LibraryImport`
generator's marshalling stubs (irrelevant here — every declaration is already blittable), and
`<IsAotCompatible>`, which netstandard2.0 cannot declare. Nothing in the raw layer is
AOT-hostile, so a future multi-target could reinstate it for the `net8.0` leg.

`CompatTests` covers the hand-written substitutes — the UTF-8 conversions, the allocator and the
argument guards — and, like the header-parity checks, needs no native library to run.

## The object model

One class per **owned** opaque handle, named after the handle minus the `PrismPdf` prefix — the
inventory the guide fixes:

| Handle | C# type | Released by |
|---|---|---|
| `PrismPdfDocument` | `Document` | `Dispose()` → `prismpdf_document_free` |
| `PrismPdfOpenOptions` | `OpenOptions` | `Dispose()` |
| `PrismPdfOpenReport` | `OpenReport` | `Dispose()` |
| `PrismPdfTransformReport` | `TransformReport` | `Dispose()` |
| `PrismPdfSignSettings` | `SignSettings` | `Dispose()` |
| `PrismPdf*List` | `AnnotationList`, `FormFieldList`, `OutlineList`, `AttachmentList`, `FontList`, `ImageList`, `SignatureList`, `StringList` | `Dispose()` |
| `PrismPdfErrorInfo` | *(none)* | internal to `PrismPdfException`; never public API |

The seven **borrowed** item types become lightweight non-owning wrappers deriving from
`BorrowedItem`: `Annotation`, `FormField`, `OutlineItem`, `Attachment`, `Font`, `Image`,
`Signature`. Each holds a strong reference to its list, so the collector cannot free the list while
an item is reachable, and checks that reference on every access, so using an item after its list
was disposed raises `ObjectDisposedException` rather than reading freed memory.

### There is no `Page` type

The ABI has no page handle. Page-indexed calls take a page index on the document:

```csharp
doc.PageText(0);
doc.PageAnnotations(0);
doc.PageImages(0);
```

The guide is blunt about why: *"A binding that grows a `Page` façade diverges from every other
binding for zero capability gain."* Resist the temptation; a `Page` object would have to either
hold a document reference and an index (a wrapper that adds nothing) or cache page state (a wrapper
that can go stale).

### The boundary is immutable

Every transform serialises a **new** document and leaves its input untouched:

```csharp
var rotated = doc.RotatePage(0, 90);   // returns bytes
// doc is unchanged — always
```

So there is never any aliasing to reason about, and no `doc.Save()` that quietly mutates. When you
want the result as a document, reopen it — which is also how the conformance suite asserts, because
round-tripping through the SDK's own read API is what a consumer actually does.

## Where each contract is enforced

| Contract | Enforced in |
|---|---|
| One error type; read the diagnostic immediately, same thread | `PrismPdfException.Create` |
| `NotFound` on an optional getter is absence | `Native.CheckOptional`, used by every optional property |
| Consuming calls invalidate on success only | `PrismPdfHandle.MarkConsumed` |
| Borrowed items keep their owner alive | `BorrowedItem` |
| Copy, then free, immediately | `Native.TakeString`, `Native.TakeBytes` |
| No shared mutable handles across threads | Documented, not enforced — see [ownership](ownership.md) |

Each of those has a test in `FailurePathTests`. If you change one of those helpers, that fixture is
the thing that tells you whether you broke the contract.
